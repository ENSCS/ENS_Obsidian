## 1. Claude คืออะไร?

Claude คือ AI Assistant ที่พัฒนาโดย **Anthropic** บริษัท AI Safety จากสหรัฐอเมริกา ออกแบบมาให้เป็น AI ที่ฉลาด ซื่อสัตย์ และปลอดภัย

### Claude ทำอะไรได้บ้าง

```
✅ อ่านและเขียนข้อความ ทุกภาษา รวมถึงภาษาไทย
✅ วิเคราะห์และสรุปเอกสาร
✅ เขียนโค้ดและแก้ bug
✅ ตอบคำถามและให้คำแนะนำ
✅ สร้างเนื้อหาสร้างสรรค์
✅ วิเคราะห์รูปภาพ
✅ ทำงานอัตโนมัติผ่าน API
```

### Claude เข้าถึงได้หลายช่องทาง

| ช่องทาง | เหมาะกับ | ราคา |
|---|---|---|
| claude.ai (เว็บ/แอป) | ใช้งานทั่วไป | Free / Pro $20/เดือน |
| Claude API | นักพัฒนา สร้าง agent | จ่ายตาม token |
| Claude Code | งานโค้ดบน terminal | ใช้ Pro account |

### เปรียบให้เห็นภาพ

```
Claude = พนักงานอัจฉริยะที่รู้ทุกเรื่อง
พร้อมทำงานตลอด 24 ชั่วโมง ไม่เคยเหนื่อย
แค่บอกว่าต้องการอะไร — ลงมือทำให้ทันที
```

## 2. Prompt คืออะไร?

**Prompt** คือคำสั่งหรือข้อความที่คุณส่งให้ Claude — มันคือหัวใจของทุกอย่างเลย

> ถ้า Claude คือพนักงาน — Prompt คือคำสั่งงานที่คุณมอบให้

### ความแตกต่างของ Prompt ที่ดี vs ไม่ดี

**Prompt ไม่ดี:**
```
"สรุปนี้หน่อย"
```

**Prompt ที่ดี:**
```
"สรุปเอกสารนี้เป็นภาษาไทย ความยาวไม่เกิน 5 บรรทัด
เน้นประเด็นสำคัญที่ผู้บริหารควรรู้
ใช้ภาษาเป็นทางการ"
```

### หลักการเขียน Prompt ที่ดี

**1. บอก Role — บอกว่าให้ Claude เป็นใคร**
```
"คุณคือนักบัญชีผู้เชี่ยวชาญ..."
"คุณคือครูสอนภาษาอังกฤษ..."
"คุณคือนักวิเคราะห์การลงทุน..."
```

**2. บอก Context — บอกที่มาที่ไป**
```
"ผมเป็นเจ้าของร้านอาหาร มีพนักงาน 5 คน..."
"นี่คือรายงานการเงินของบริษัท Q1/2026..."
```

**3. บอก Task — บอกว่าต้องการอะไร**
```
"ช่วยเขียนอีเมลตอบลูกค้าที่ร้องเรียนเรื่อง..."
"วิเคราะห์จุดแข็งจุดอ่อนของ..."
```

**4. บอก Format — บอกรูปแบบที่ต้องการ**
```
"ตอบเป็น bullet points 5 ข้อ"
"เขียนเป็นตาราง 3 คอลัมน์"
"ความยาวไม่เกิน 200 คำ"
```

### System Prompt vs User Prompt

```
System Prompt = "job description" ที่กำหนดบุคลิกและหน้าที่ของ Claude
User Prompt   = งานที่มอบหมายแต่ละครั้ง

System: "คุณคือผู้ช่วยฝ่าย HR เชี่ยวชาญกฎหมายแรงงานไทย"
User:   "พนักงานลาป่วยเกิน 30 วัน จะทำอย่างไร?"
```

## 3. Skill คืออะไร?

**Skill** คือ Prompt ที่เขียนไว้อย่างดี เก็บไว้ใช้ซ้ำได้ ติดตาม account ข้าม device

> ถ้า Prompt คือคำสั่งงานทั่วไป — Skill คือ "คู่มือการทำงาน" ที่เขียนละเอียดครั้งเดียว ใช้ได้ตลอด

### ความแตกต่าง

```
Prompt ธรรมดา:
พิมพ์ทุกครั้งที่ใช้ → เสียเวลา → ผลลัพธ์ไม่สม่ำเสมอ

Skill:
เขียนครั้งเดียว → เรียกใช้ทุกครั้ง → ผลลัพธ์สม่ำเสมอเสมอ
```

### ตัวอย่าง Skill จริงๆ

```
ชื่อ Skill: earnings-call-summarizer
ทำหน้าที่: สรุป Earnings Call เป็นโครงสร้าง 9 sections
ใช้เมื่อ: มี transcript Oppday ใหม่
ผลลัพธ์: Summary มาตรฐานทุกครั้ง ไม่ว่าใครจะใช้
```

### Skill เก็บไว้ที่ไหน

```
Skill ใน Claude.ai → เก็บบน Anthropic server → ติดตาม account ทุก device
ดาวน์โหลดได้เป็น .skill file → จริงๆ คือ ZIP ที่มี Markdown ข้างใน
```

### เปรียบให้เห็นภาพ

```
Skill = สูตรอาหารที่เขียนไว้ดีแล้ว
ใครได้สูตรนี้ไป ทำตามแล้วได้ผลเหมือนกันทุกครั้ง
```

## 4. Tool คืออะไร?

**Tool** คือความสามารถที่ให้ Claude ทำสิ่งที่ AI ทำเองไม่ได้ — เข้าถึงโลกภายนอก

> ถ้า Skill คือ "สอนให้คิดแบบไหน" — Tool คือ "ให้อุปกรณ์ที่ทำงานได้จริง"

### ความแตกต่างที่สำคัญ

```
Skill = ข้อความ/Prompt → Claude ฉลาดขึ้น
Tool  = โค้ดที่รันได้จริง → Claude ทำได้มากขึ้น
```

### ประเภทของ Tool

**Built-in Tools (ติดมากับ Claude.ai)**
```
Web Search    → ค้นหาข้อมูลจากอินเทอร์เน็ต
Code Execution → รันโค้ดได้จริง
Image Analysis → วิเคราะห์รูปภาพ
```

**MCP Tools (ติดตั้งเพิ่มเอง)**
```
Gmail         → อ่าน/ส่งอีเมล
Google Calendar → จัดการปฏิทิน
LINE OA       → ส่งข้อความ LINE
Notion        → จัดการ workspace
Slack         → สื่อสารในทีม
```

### Tool ต่างจาก Skill ตรงไหน

| | Skill | Tool |
|---|---|---|
| คืออะไร | Prompt/ข้อความ | โค้ดที่รันได้ |
| ติดตาม account | ✅ | ❌ ต้องติดตั้งที่เครื่อง |
| ใช้บนมือถือได้ | ✅ | ❌ |
| ตัวอย่าง | earnings-call-summarizer | ส่ง LINE, ค้นหาเว็บ |

### เปรียบให้เห็นภาพ

```
Skill = สอนให้แพทย์เชี่ยวชาญด้านหัวใจ (ความรู้)
Tool  = ให้เครื่อง ECG ใช้ตรวจคนไข้ (อุปกรณ์)

แพทย์ที่เชี่ยวชาญ + มีเครื่องมือ = ทำงานได้ดีที่สุด
```

## 5. Agent คืออะไร?

**Agent** คือ AI ที่รับเป้าหมาย แล้วคิดและลงมือทำเองหลาย step โดยไม่ต้องให้คนสั่งทุกขั้น

> ถ้า Claude ใน chat คือ "ที่ปรึกษา" — Agent คือ "พนักงานที่รับงานแล้วทำจนเสร็จเอง"

### ความแตกต่าง

| | Claude ใน Chat | Agent |
|---|---|---|
| การทำงาน | ถาม-ตอบ วนซ้ำ | รับงาน → คิด → ทำ → รายงาน |
| ผู้ควบคุม Flow | มนุษย์สั่งทุก step | AI ตัดสินใจเอง |
| ใช้ Tools | ไม่จำเป็น | หัวใจหลัก |
| ตัวอย่าง | "ช่วยสรุปนี้หน่อย" | "สรุป Oppday ทุกบริษัทแล้วส่ง LINE" |

### องค์ประกอบของ Agent

```
Agent ที่ดีต้องมี:
1. เป้าหมาย    → รู้ว่าต้องทำอะไร
2. Tools       → มีอุปกรณ์ทำงานได้จริง
3. Logic       → รู้ว่าทำขั้นตอนไหนก่อน-หลัง
4. Error handling → รับมือเมื่อมีปัญหา
5. Output      → ส่งผลลัพธ์ออกมา
```

### Agent สร้างได้จากอะไร

```
Python (.py)     → ยืดหยุ่นที่สุด ควบคุมได้เต็มที่
n8n / Make       → No-code ลากวางได้เลย
Claude Code      → รันบน terminal ใช้ Pro account
JavaScript (.js) → รันบน Node.js
```

### ตัวอย่าง Agent จริงๆ

```
oppday_agent.py:
รับ: โฟลเดอร์ที่มีไฟล์ transcript .txt
ทำ: อ่านไฟล์ → detect ticker → สรุปด้วย Claude API → บันทึก .md
ข้าม: ไฟล์ที่สรุปแล้ว
รายงาน: สรุปผลว่าทำกี่ไฟล์ ข้ามกี่ไฟล์
```

### เปรียบให้เห็นภาพ

```
Chat ปกติ = โทรถามที่ปรึกษาทุกครั้งที่มีคำถาม
Agent     = จ้างพนักงานประจำที่รับงานแล้วทำจนเสร็จเอง
```

## 6. Memory คืออะไร?

**Memory** คือความสามารถให้ Claude จำข้อมูลข้ามการสนทนาได้

> ปัญหาหลักของ Claude: ทุก API call เริ่มใหม่หมด จำอะไรจากครั้งก่อนไม่ได้เลย

### Memory 4 ประเภท

**1. In-context Memory**
```
เก็บข้อมูลไว้ใน messages ที่ส่งไปพร้อมกัน
ข้อดี: ง่ายมาก
ข้อเสีย: หายเมื่อปิด session
เหมาะกับ: งานในครั้งเดียว
```

**2. External Memory (แนะนำที่สุดสำหรับงานทั่วไป)**
```
บันทึกลงไฟล์ .json แล้วโหลดกลับมาทุกครั้ง
ข้อดี: จำได้ถาวร ข้ามครั้งได้
ข้อเสีย: ต้อง paste เองเมื่อเริ่ม session ใหม่
เหมาะกับ: วิเคราะห์หุ้นต่อเนื่อง, project ยาว
```

**3. Summary Memory**
```
สรุปการสนทนาก่อนหน้าเก็บไว้ ไม่เก็บทุกอย่าง
ข้อดี: ประหยัด token
ข้อเสีย: อาจตกหล่นรายละเอียด
เหมาะกับ: conversation ยาวที่ต้องการต่อเนื่อง
```

**4. RAG (Semantic Memory)**
```
เก็บเอกสารเยอะๆ ดึงเฉพาะส่วนที่เกี่ยวข้องมาใช้
ข้อดี: รองรับข้อมูลมหาศาล
ข้อเสีย: ต้องตั้งค่าระบบ
เหมาะกับ: knowledge base ขนาดใหญ่
```

### วิธีใช้ External Memory ใน Chat

```
วิธีง่ายที่สุด:

1. ก่อนปิด chat: "สรุปสิ่งที่คุยไปเป็น JSON ให้หน่อย"
2. Copy JSON ที่ได้ → เก็บในไฟล์ หรือ Notion/Obsidian
3. ครั้งหน้า: paste JSON + "นี่คือ context เดิม คุยต่อได้เลย"
```

### ตัวอย่าง Memory JSON สำหรับการวิเคราะห์หุ้น

```json
{
  "ticker": "BEM",
  "last_updated": "2026-06-10",
  "current_view": "BUY",
  "open_questions": ["capex แผน 3 ปี", "สัมปทาน MRT"],
  "sessions": [
    {"date": "2026-06-01", "summary": "Q1 กำไรโต 12% YoY"},
    {"date": "2026-06-10", "summary": "ข่าวต่อสัมปทานทางด่วน 20 ปี"}
  ]
}
```

## 7. Multi-agent คืออะไร?

**Multi-agent** คือการใช้ Agent หลายตัวทำงานร่วมกัน แต่ละตัวเชี่ยวชาญคนละด้าน

> แทนที่จะให้คนเดียวทำทุกอย่าง — แบ่งงานให้ทีมทำ

### 3 Pattern หลัก

**1. Sequential — ทำต่อกันเป็นสาย**
```
Agent 1 (ดึงข้อมูล) → Agent 2 (วิเคราะห์) → Agent 3 (รายงาน)
เหมาะกับ: งานที่ต้องทำตามลำดับ
```

**2. Parallel — ทำพร้อมกัน**
```
Agent 1 ─┐
Agent 2 ─┼→ Agent รวมผล
Agent 3 ─┘
เหมาะกับ: งานที่แบ่งแยกได้ อยากประหยัดเวลา
```

**3. Supervisor — มีหัวหน้าคุม**
```
Supervisor Agent
├── สั่ง Agent 1
├── สั่ง Agent 2
└── รวมผลและตัดสินใจ
เหมาะกับ: งานซับซ้อนที่ต้องการการตัดสินใจหลายชั้น
```

### แต่ละ Agent รู้ได้ไงว่าต้องทำงานต่อจากใคร

```
Agent ไม่รู้จักกันเลย — โค้ดเป็นคนส่งงานต่อให้

เหมือนสายพานการผลิต:
พนักงานแต่ละคนรู้แค่ว่า "รับงานจากซ้าย ส่งงานไปขวา"
ไม่รู้ว่าสายพานมีกี่ขั้น
```

### เมื่อไหรควรใช้ Multi-agent

```
✅ งานช้าเกินไป → แยกทำ Parallel
✅ งานซับซ้อนจนคุณภาพลด → แยกให้แต่ละตัวโฟกัส
✅ อยากเพิ่มงานใหม่โดยไม่แตะโค้ดเดิม

❌ งานง่ายๆ flow ตายตัว → Agent เดียวพอ
❌ งานที่ทำได้ดีอยู่แล้ว → ไม่จำเป็นต้องแยก
```

## 8. RAG คืออะไร?

**RAG** ย่อมาจาก Retrieval-Augmented Generation คือการให้ Claude ตอบจากเอกสารจำนวนมากได้อย่างแม่นยำ

> ปัญหา: ส่งเอกสาร 500 ไฟล์เข้า context ไม่ได้ — token เกิน
> RAG แก้: ดึงเฉพาะส่วนที่เกี่ยวข้องมาใส่ context

### RAG ทำงานยังไง

```
ขั้นที่ 1 — เตรียมข้อมูล (ทำครั้งเดียว)
เอกสารทั้งหมด → แบ่งเป็นชิ้นเล็กๆ → แปลงเป็น Vector → เก็บใน Vector DB

ขั้นที่ 2 — ตอบคำถาม (ทุกครั้งที่ถาม)
คำถาม → แปลงเป็น Vector → หาชิ้นที่ใกล้เคียง → ส่งให้ Claude ตอบ
```

### Vector คืออะไร

```
Vector = ตัวเลขที่แทนความหมายของข้อความ

"capex การลงทุน" → [0.2, 0.8, 0.1, 0.9, ...]
"กำไรสุทธิ"      → [0.7, 0.1, 0.9, 0.2, ...]

ความหมายใกล้กัน → ตัวเลขใกล้กัน
เหมือนแผนที่ความหมาย
```

### เครื่องมือที่ใช้สร้าง RAG

| ส่วน | เครื่องมือแนะนำ | ราคา |
|---|---|---|
| Embedding | OpenAI text-embedding-3-small | จ่ายต่อ token (ถูกมาก) |
| Vector DB | ChromaDB | ฟรี รันบนเครื่อง |
| Framework | LlamaIndex | ฟรี |
| LLM | Claude API | มีอยู่แล้ว |

### ทางเลือกที่ไม่ต้องเขียนโค้ด

```
NotebookLM (Google) → upload ไฟล์ → ถามได้เลย → ฟรี
เหมาะกับ: ใช้งานส่วนตัว ไม่ต้องการ automation
```

### ทุกอย่างเชื่อมกันอย่างไร

```
┌─────────────────────────────────────────────────┐
│                    CLAUDE                        │
│                                                  │
│  Prompt ──→ Skill ──→ บอกให้คิดแบบไหน           │
│  Tool  ──→ ทำสิ่งที่ AI ทำเองไม่ได้              │
│  Memory ──→ จำข้อมูลข้ามครั้ง                    │
│                                                  │
└─────────────────────────────────────────────────┘
              ↓ รวมกันเป็น
┌─────────────────────────────────────────────────┐
│                    AGENT                         │
│  รับเป้าหมาย → คิดเอง → ใช้ Tool → ทำจนเสร็จ   │
└─────────────────────────────────────────────────┘
              ↓ หลายตัวรวมกันเป็น
┌─────────────────────────────────────────────────┐
│                MULTI-AGENT SYSTEM                │
│  Agent 1 + Agent 2 + Agent 3 → งานซับซ้อน       │
└─────────────────────────────────────────────────┘
```

### สรุปเปรียบเทียบ

| สิ่ง | คืออะไร | เก็บที่ไหน | ใครควรใช้ |
|---|---|---|---|
| Prompt | คำสั่งให้ Claude | ในหัว / ในโค้ด | ทุกคน |
| Skill | Prompt ที่เก็บไว้ดีๆ | Anthropic server | ใช้ Claude.ai บ่อย |
| Tool | โค้ดที่รันได้จริง | เครื่องตัวเอง | มี Claude Desktop |
| Agent | ระบบที่ทำงานอัตโนมัติ | เครื่องตัวเอง | นักพัฒนา |
| Memory | วิธีให้ Claude จำข้อมูล | ไฟล์ / DB | งานต่อเนื่อง |
| RAG | ค้นหาในเอกสารเยอะๆ | Vector DB | ข้อมูลมาก |
| Multi-agent | หลาย Agent ทำงานร่วมกัน | เครื่องตัวเอง | งานซับซ้อน |

## บทสรุป: เริ่มต้นอย่างไรดี?

### Roadmap สำหรับผู้เริ่มต้น

```
สัปดาห์ที่ 1-2: พื้นฐาน
→ ใช้ Claude.ai chat ทุกวัน
→ ฝึกเขียน Prompt ที่ดี
→ ลอง Use Case 1-5

สัปดาห์ที่ 3-4: ระดับกลาง
→ สร้าง Skill แรกของตัวเอง
→ ลอง Use Case 6-9
→ ทดลองใช้ Memory (JSON)

เดือนที่ 2: Advanced
→ สมัคร Anthropic API
→ ลอง Claude Code
→ สร้าง Agent แรก (.py)
→ ลอง Use Case 10-12

เดือนที่ 3+: Pro
→ สร้าง Multi-agent system
→ ตั้ง RAG จากเอกสารของตัวเอง
→ Automate งาน routine ทั้งหมด
→ Use Case 13-15
```

### หลักการสำคัญที่ควรจำ

```
1. Prompt คือทุกอย่าง — ยิ่งบอกละเอียด ยิ่งได้ผลดี
2. Skill = Prompt ที่ดี เก็บไว้ใช้ซ้ำ
3. Tool ต้องติดตั้งที่เครื่อง ไม่ติดตาม account
4. Agent ไม่ใช่ไฟล์ — มันคือแนวคิดการทำงาน
5. เริ่มจาก Agent เดียวก่อน ค่อยแยก Multi-agent เมื่อจำเป็น
6. Memory ที่ง่ายที่สุดคือ JSON paste เข้า chat
7. RAG เหมาะกับเอกสารเยอะ ถ้าน้อยใช้ NotebookLM พอ
```
