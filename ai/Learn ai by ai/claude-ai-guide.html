บทที่ 01
Claude คืออะไร?

Claude คือ AI Assistant ที่พัฒนาโดย Anthropic บริษัท AI Safety จากสหรัฐอเมริกา ออกแบบมาให้เป็น AI ที่ฉลาด ซื่อสัตย์ และปลอดภัย Claude ไม่ใช่แค่ chatbot ธรรมดา — มันคือผู้ช่วยที่อ่านเขียนได้ทุกภาษา วิเคราะห์เอกสารได้ เขียนโค้ดได้ และทำงานอัตโนมัติได้ด้วย

Claude ทำอะไรได้บ้าง

✅ อ่านและเขียนข้อความทุกภาษา รวมถึงภาษาไทย
✅ วิเคราะห์และสรุปเอกสาร PDF, Word, Excel
✅ เขียนโค้ดและแก้ bug
✅ ตอบคำถามและให้คำแนะนำ
✅ สร้างเนื้อหาสร้างสรรค์ เช่น บทความ อีเมล รายงาน
✅ วิเคราะห์รูปภาพ
✅ ทำงานอัตโนมัติผ่าน API

Claude เข้าถึงได้หลายช่องทาง

ช่องทางเหมาะกับราคา
claude.ai (เว็บ/แอป)ใช้งานทั่วไปFree / Pro $20/เดือน
Claude APIนักพัฒนา สร้าง Agentจ่ายตาม Token
Claude Codeงานโค้ดบน terminalใช้ Pro account
Claude Desktopใช้ Tool และ MCPใช้ Pro account
Claude = พนักงานอัจฉริยะที่รู้ทุกเรื่อง พร้อมทำงานตลอด 24 ชั่วโมง ไม่เคยเหนื่อย แค่บอกว่าต้องการอะไร — ลงมือทำให้ทันที

บทที่ 02
Prompt คืออะไร และเขียนอย่างไรให้ได้ผลดี

Prompt คือคำสั่งหรือข้อความที่คุณส่งให้ Claude — มันคือหัวใจของทุกอย่างเลย ยิ่งบอก Claude ละเอียดและชัดเจนเท่าไหร่ ผลลัพธ์ที่ได้ก็จะดีขึ้นเท่านั้น

ถ้า Claude คือพนักงาน — Prompt คือคำสั่งงานที่คุณมอบให้

Prompt ที่ดี vs ไม่ดี

❌ ไม่ดี
"สรุปนี้หน่อย"
✅ ดี
"สรุปเอกสารนี้เป็นภาษาไทย
ไม่เกิน 5 บรรทัด เน้นประเด็นสำคัญ
ที่ผู้บริหารควรรู้ ใช้ภาษาทางการ"

RCTF Framework

R — Role:    "คุณคือนักบัญชีผู้เชี่ยวชาญ..."
C — Context: "ผมเป็นเจ้าของร้านอาหาร มีพนักงาน 5 คน..."
T — Task:    "ช่วยเขียนอีเมลตอบลูกค้าที่ร้องเรียน..."
F — Format:  "ตอบเป็น bullet points 5 ข้อ ภาษาทางการ"

XML Template (Copy ไปใช้ได้เลย)

<role>คุณคือผู้เชี่ยวชาญด้าน...</role>
<context>[ข้อมูลหรือเอกสาร]</context>
<instruction>[คำสั่งที่ต้องการ]</instruction>
<format>ภาษาไทย กระชับ อ่านเข้าใจง่าย</format>

System Prompt vs User Prompt

System Prompt = "job description" บอกครั้งเดียว ใช้ตลอด session
User Prompt   = งานที่มอบหมายแต่ละครั้ง เปลี่ยนทุกครั้ง
📚
บทที่ 03
Skill คืออะไร?

Skill คือ Prompt ที่เขียนไว้อย่างดี เก็บไว้ใช้ซ้ำได้ ติดตาม account ข้าม device แทนที่จะพิมพ์คำสั่งยาวๆ ซ้ำทุกครั้ง — เขียนครั้งเดียวแล้วเก็บไว้เป็น Skill ใช้ได้ตลอด

ถ้า Prompt คือคำสั่งงานทั่วไป — Skill คือ "คู่มือการทำงาน" ที่เขียนละเอียดครั้งเดียว ใช้ได้ตลอด
❌ ไม่มี Skill

ทุกครั้งที่อยากสรุป → พิมพ์คำสั่งยาวๆ ใหม่ → เสียเวลา → ผลลัพธ์ไม่สม่ำเสมอ

✅ มี Skill

สร้าง Skill ครั้งเดียว → เรียกใช้ทันที → ผลลัพธ์สม่ำเสมอทุกครั้ง

ตัวอย่าง Skill จริงๆ

ชื่อ:    earnings-call-summarizer
ทำหน้าที่: สรุป Earnings Call เป็นโครงสร้าง 9 sections
ใช้เมื่อ:  มี transcript Oppday ใหม่
ผลลัพธ์:  Summary มาตรฐานทุกครั้ง ไม่ว่าใครจะใช้
💡 ข้อดี
เก็บบน Anthropic server ติดตาม account ทุก device / ดาวน์โหลดได้เป็น .skill file / แชร์ให้คนอื่น import ได้
🔧
บทที่ 04
Tool คืออะไร?

Tool คือความสามารถที่ให้ Claude ทำสิ่งที่ AI ทำเองไม่ได้ — เข้าถึงโลกภายนอก

ถ้า Skill คือ "สอนให้คิดแบบไหน" — Tool คือ "ให้อุปกรณ์ที่ทำงานได้จริง"

ประเภทของ Tool

Built-in Tools — ติดมากับ Claude.ai ใช้ได้เลย
Web Search     → ค้นหาข้อมูลจากอินเทอร์เน็ต real-time
Code Execution → รันโค้ดได้จริงและแสดงผล
Image Analysis → วิเคราะห์และอธิบายรูปภาพ

MCP Tools — ติดตั้งเพิ่มเองผ่าน Claude Desktop
Gmail, Google Calendar, LINE OA, Notion, Slack, Google Drive
📱 Skill

เปิด claude.ai บนมือถือก็ใช้ได้เลย — ติดตาม account

💻 Tool

ต้องเปิด Claude Desktop บนเครื่องที่ติดตั้งไว้เท่านั้น

Skill = สอนให้แพทย์เชี่ยวชาญด้านหัวใจ (ความรู้)
Tool = ให้เครื่อง ECG ใช้ตรวจคนไข้ (อุปกรณ์)
แพทย์ที่เชี่ยวชาญ + มีเครื่องมือ = ทำงานได้ดีที่สุด
🎨
บทที่ 05
Artifacts คืออะไร?

Artifacts คือผลลัพธ์ที่ Claude สร้างออกมาเป็น "ชิ้นงานจริง" ที่ใช้งานได้เลย ไม่ใช่แค่ข้อความในกล่องสนทนา

ไม่มี Artifacts = ช่างบอกวิธีสร้างโต๊ะ
มี Artifacts = ช่างสร้างโต๊ะให้เสร็จแล้ววางตรงหน้าคุณ
ประเภทตัวอย่างข้อดี
HTML / เว็บเพจLanding Page, Dashboardเปิดดูได้ทันทีใน chat
โค้ด Python/JS/PHPScript อัตโนมัติพร้อม copy ไปใช้
Markdown / เอกสารรายงาน, บทความExport เป็นไฟล์ได้
SVG / รูปภาพDiagram, Chartแก้ไขได้ง่าย
💡 วิธีใช้
ไม่ต้องทำอะไรพิเศษ แค่สั่งให้ Claude สร้างสิ่งที่ต้องการ — Claude จะตัดสินใจเองว่าควรสร้างเป็น Artifact หรือไม่
⚙️
บทที่ 06
Agent คืออะไร?

Agent คือ AI ที่รับเป้าหมาย แล้วคิดและลงมือทำเองหลาย step โดยไม่ต้องให้คนสั่งทุกขั้น นี่คือการยกระดับจาก "ถาม-ตอบ" ไปสู่ "รับงานแล้วทำจนเสร็จ"

ถ้า Claude ใน chat คือ "ที่ปรึกษา" — Agent คือ "พนักงานที่รับงานแล้วทำจนเสร็จเอง"
Claude ใน ChatAgent
การทำงานถาม-ตอบ วนซ้ำรับงาน → คิด → ทำ → รายงาน
ผู้ควบคุมมนุษย์สั่งทุก stepAI ตัดสินใจเอง
ตัวอย่าง"ช่วยสรุปนี้หน่อย""สรุป Oppday ทุกบริษัทแล้วส่ง LINE"

องค์ประกอบของ Agent ที่ดี

1. เป้าหมาย       → รู้ว่าต้องทำอะไร
2. Tools          → มีอุปกรณ์ทำงานได้จริง
3. Logic          → รู้ว่าทำขั้นตอนไหนก่อน-หลัง
4. Error handling → รับมือเมื่อมีปัญหา
5. Output         → ส่งผลลัพธ์ในรูปแบบที่ต้องการ

Agent สร้างได้จากอะไร

Python (.py)     → ยืดหยุ่นที่สุด ควบคุมได้เต็มที่
JavaScript (.js) → รันบน Node.js
Claude Code      → รันบน terminal ใช้ Pro account
n8n / Make       → No-code ลากวางได้เลย

บทที่ 07
Memory คืออะไร?

Memory คือความสามารถให้ Claude จำข้อมูลข้ามการสนทนาได้ ปัญหาหลักของ Claude คือทุก chat ใหม่ = เริ่มใหม่หมด จำอะไรจากครั้งก่อนไม่ได้เลย

Memory 4 ประเภท

In-context
จำในการสนทนาเดียวกัน

ง่ายมาก แต่หายเมื่อปิด chat / เหมาะกับงานในครั้งเดียว

External ⭐
บันทึกไว้ในไฟล์ (แนะนำที่สุด)

จำได้ถาวร ข้ามครั้งได้ / ต้อง paste เอง

Summary
สรุปไว้แล้วเก็บ

ประหยัด token / อาจตกหล่นรายละเอียด

RAG
ค้นหาในเอกสารเยอะๆ

รองรับข้อมูลมหาศาล / ต้องตั้งค่าระบบ

วิธีใช้ External Memory ง่ายๆ

ขั้นที่ 1: ก่อนปิด chat → "สรุปสิ่งที่คุยไปทั้งหมดเป็น JSON"
ขั้นที่ 2: Copy JSON เก็บไว้ใน Notion, Obsidian, หรือไฟล์ .json
ขั้นที่ 3: ครั้งหน้า → Paste JSON + "นี่คือ context เดิม คุยต่อได้เลย"

บทที่ 08
Multi-agent คืออะไร?

Multi-agent คือการใช้ Agent หลายตัวทำงานร่วมกัน แต่ละตัวเชี่ยวชาญคนละด้าน แทนที่จะให้ Agent เดียวทำทุกอย่าง

เหมือนบริษัทที่มีพนักงานหลายคน แทนที่จะให้คนเดียวทำทุกอย่าง

3 Pattern หลัก

1. Sequential — ทำต่อกันเป็นสาย
Agent 1 (ดึงข้อมูล) → Agent 2 (วิเคราะห์) → Agent 3 (รายงาน)

2. Parallel — ทำพร้อมกัน
Agent 1 ─┐
Agent 2 ─┼→ Agent รวมผล → Output (ประหยัดเวลา)
Agent 3 ─┘

3. Supervisor — มีหัวหน้าคุม
Supervisor Agent
├── สั่ง Agent 1 → รับผล
├── สั่ง Agent 2 → รับผล
└── รวมผลและตัดสินใจขั้นสุดท้าย

บทที่ 09
ภาพรวมทั้งหมด: ทุกอย่างเชื่อมกันอย่างไร
┌────────────────────────────────────────────┐
│                  CLAUDE                     │
│  Prompt + Skill → บอกให้คิดแบบไหน          │
│  Tool           → ทำสิ่งที่ AI เองไม่ได้    │
│  Artifacts      → สร้างผลงานจริง            │
│  Memory         → จำข้อมูลข้ามครั้ง         │
└────────────────────────────────────────────┘
                ↓ รวมกันเป็น
┌────────────────────────────────────────────┐
│                  AGENT                      │
│  รับเป้าหมาย → คิดเอง → ใช้ Tool → ทำเสร็จ │
└────────────────────────────────────────────┘
                ↓ หลายตัวรวมกันเป็น
┌────────────────────────────────────────────┐
│           MULTI-AGENT SYSTEM                │
│  Agent 1 + Agent 2 + Agent 3 → งานซับซ้อน  │
└────────────────────────────────────────────┘
สิ่งคืออะไรเก็บที่ไหนใครควรใช้
Promptคำสั่งให้ Claudeในหัว / ในโค้ดทุกคน
SkillPrompt ที่เก็บไว้ดีๆAnthropic serverใช้ Claude.ai บ่อย
Toolโค้ดที่รันได้จริงเครื่องตัวเองมี Claude Desktop
Artifactsผลงานพร้อมใช้ใน chatใน chatทุกคน
Agentระบบที่ทำงานอัตโนมัติเครื่องตัวเองนักพัฒนา
Memoryวิธีให้ Claude จำข้อมูลไฟล์ / DBงานต่อเนื่อง
Multi-agentหลาย Agent ทำงานร่วมกันเครื่องตัวเองงานซับซ้อน

บทที่ 10
Use Cases: ตั้งแต่ง่ายจนถึงซับซ้อน (15 Cases)
🟢 ระดับเริ่มต้น — ใช้ Chat ปกติ

Case 1: เขียนอีเมลและเอกสารทางการ ⭐

เครื่องมือ: Claude.ai chat
Prompt: "เขียนอีเมลภาษาอังกฤษติดตามใบเสนอราคาที่ส่งให้ Mr. John Smith
ใช้ภาษาสุภาพ เป็นมืออาชีพ ไม่เกิน 5 ประโยค"
⏱ ประหยัดเวลา: 30 นาที → 2 นาที

Case 2: สรุปเอกสารยาวสำหรับผู้บริหาร ⭐

เครื่องมือ: Claude.ai + แนบไฟล์
Prompt: "สรุปเอกสารนี้เป็นภาษาไทย ไม่เกิน 1 หน้า เน้น 3 ประเด็นหลักที่ผู้บริหารควรรู้"
⏱ ประหยัดเวลา: 2 ชั่วโมง → 5 นาที

Case 3: ผู้ช่วยสอนและติวหนังสือ ⭐

เครื่องมือ: Claude.ai chat
Prompt: "อธิบาย compound interest ให้ฉันเข้าใจ ฉันไม่มีพื้นฐานการเงิน
ใช้ตัวอย่างที่เห็นภาพได้ชัด แล้วออกแบบฝึกหัด 3 ข้อ"
ผลลัพธ์: ครูส่วนตัวตลอด 24 ชั่วโมง ถามซ้ำได้ไม่จำกัด

Case 4: วิเคราะห์ข้อมูลและทำรายงาน ⭐⭐

เครื่องมือ: Claude.ai + แนบไฟล์ Excel/CSV
Prompt: "วิเคราะห์ยอดขาย 12 เดือน บอก trend, เดือนดีสุด/แย่สุด, คำแนะนำ 3 ข้อ"

Case 5: เขียน Content โซเชียลมีเดีย ⭐⭐

ผลลัพธ์: Content 7 วัน caption + hashtag + CTA ประหยัด 3 ชม. → 10 นาที

Case 6: วิเคราะห์รูปภาพด้วย Vision ⭐⭐

แค่แนบรูปแล้วถามได้เลย:
→ ถ่ายรูปใบเสร็จ → สกัดข้อมูลเป็นตาราง
→ วาด wireframe บนกระดาษ → Claude แปลงเป็น HTML
→ ถ่ายรูปกราฟ → วิเคราะห์ trend และ insight
→ ถ่ายรูปนามบัตร → แปลงเป็น JSON
🟡 ระดับกลาง — ใช้ Skill + Tool + Artifacts

บทที่ 12 — ระดับ 1
Token & Context Window

Token คือหน่วยที่ Claude ใช้อ่านและเขียนข้อความ มีผลต่อ 2 อย่าง: ราคา (API คิดเงินตาม token) และ ข้อจำกัด (Context Window)

ภาษาอังกฤษ: "Hello world" = 2 tokens (1 คำ ≈ 1 token)
ภาษาไทย:   "สวัสดีครับ" = ประมาณ 8-12 tokens
(ภาษาไทยใช้ token มากกว่าอังกฤษ 3-4 เท่า)

Context Window = ความจำระยะสั้นของ Claude

Claude Sonnet / Opus → ~200,000 tokens ≈ หนังสือ 150-200 หน้า
⚠️ ปัญหาที่พบบ่อย
Claude ลืมสิ่งที่คุยไว้ตอนต้น → เพราะ context เต็ม ของเก่าถูกดันออก
Claude ตอบแปลกๆ เมื่อส่งไฟล์ใหญ่ → เพราะไฟล์กินพื้นที่จนเหลือน้อยมาก

วิธีรับมือ

✅ แบ่งเอกสารยาวๆ ออกเป็นส่วนๆ
✅ เริ่ม chat ใหม่เมื่อ conversation ยาวเกินไป
✅ ใช้ RAG แทนการส่งเอกสารทั้งหมด
✅ สรุป chat เก่าแล้ว paste เข้า chat ใหม่

Privacy & Security
ช่องทางการเก็บข้อมูลเหมาะกับ

บทที่ 16 — ระดับ 2
Prompt Engineering เชิงลึก

Technique 1: Chain of Thought (CoT)

บอกให้ Claude คิดทีละขั้นก่อนตอบ ใช้ประโยค "คิดทีละขั้นตอน แสดงการคำนวณทุกขั้น"

เหมาะกับ: คณิตศาสตร์, logic, การตัดสินใจซับซ้อน

Technique 2: Few-shot Examples

"แปลง feedback ลูกค้าเป็น action item ตามตัวอย่างนี้:
ตัวอย่าง: Input: 'ส่งของช้ามาก' → Output: [โลจิสติกส์] ตรวจสอบระยะเวลาจัดส่ง
ตอนนี้แปลงนี้ให้หน่อย: 'เว็บไซต์ใช้งานยาก'"

Technique 3: Negative Prompting

"ห้าม: ใช้คำว่า 'รับประกัน' หรือ 'แน่นอน'
ห้าม: แนะนำหุ้นตัวใดตัวหนึ่งโดยตรง"

Technique 4: Output Format ที่แม่นยำ

"ตอบใน JSON format นี้เท่านั้น:
{'company': 'ชื่อ', 'strengths': [], 'threat_level': 'สูง/กลาง/ต่ำ'}"

Technique 5: Iterative Refinement

ครั้งที่ 1: "เขียนบทนำ"
ครั้งที่ 2: "เพิ่ม hook ตอนต้น"
ครั้งที่ 3: "สั้นลง 30% โดยไม่เสียใจความ"

Technique 6: XML Tags — วิธีที่ Anthropic แนะนำ

<role>       → บอกว่า Claude เป็นใคร
<context>    → ข้อมูลพื้นหลัง
<instruction> → คำสั่งที่ต้องการ
<example>    → ตัวอย่าง input/output
<data>       → ข้อมูลที่ต้องวิเคราะห์
<format>     → รูปแบบที่ต้องการ
<constraint> → ข้อจำกัด/สิ่งที่ห้ามทำ
💡 ทำไมต้องใช้ XML Tags
Claude แยกแยะ context, คำสั่ง, และข้อมูลออกจากกันได้ชัดเจน → ผลลัพธ์แม่นยำและสม่ำเสมอกว่า → ลด token ที่ต้องใช้

RAG คืออะไรและใช้งานจริง

RAG (Retrieval-Augmented Generation) = การให้ Claude ตอบจากเอกสารจำนวนมากได้อย่างแม่นยำ โดยดึงเฉพาะส่วนที่เกี่ยวข้องมาใส่ context

เหมือนห้องสมุดที่มีบรรณารักษ์: คุณถาม → บรรณารักษ์หยิบหนังสือที่เกี่ยวข้องมา 3-5 เล่ม → Claude อ่านแค่นั้น → ตอบได้แม่นยำ ไม่ต้องอ่านทุกเล่ม

RAG ทำงานอย่างไร?

ขั้นที่ 1 — เตรียมข้อมูล (ทำครั้งเดียว)
เอกสารทั้งหมด → แบ่งเป็นชิ้นเล็กๆ (chunk)
→ แปลงเป็น Vector → เก็บใน Vector Database

ขั้นที่ 2 — ตอบคำถาม (ทุกครั้ง)
คำถาม → แปลงเป็น Vector → หาชิ้นที่ความหมายใกล้เคียง
→ ดึงมา 5-10 ชิ้น → ส่งให้ Claude ตอบ

ทางเลือกที่ไม่ต้องเขียนโค้ด

NotebookLM (แนะนำสำหรับมือใหม่)
→ ฟรีจาก Google ที่ notebook.google.com
→ Upload ไฟล์ → ถามได้เลย พร้อมอ้างอิงหน้าที่มา
→ เหมาะกับ: เอกสารไม่เกิน 50 ไฟล์

สร้าง RAG เองด้วยโค้ด
→ LlamaIndex + ChromaDB

Function Calling คือความสามารถที่ให้ Claude "เรียกใช้ฟังก์ชัน" ที่เราเขียนไว้ได้เอง โดย Claude ตัดสินใจเองว่าควรเรียกเมื่อไหร่และด้วยข้อมูลอะไร

⚠️ จุดสำคัญที่มือใหม่มักเข้าใจผิด
Claude ไม่ได้รัน function เอง — Claude แค่บอกว่า "ขอเรียก function นี้ด้วย input นี้" โค้ดเราต้องรัน function แล้วส่งผลกลับไปให้ Claude เอง

Flow การทำงาน 5 ขั้น

1. คุณบอก Claude ว่ามี function อะไรให้ใช้บ้าง
   เช่น get_stock_price, send_email, search_web

2. ผู้ใช้ถาม "ราคา PTT วันนี้เท่าไหร่?"

3. Claude ตัดสินใจว่าต้องเรียก get_stock_price("PTT")

4. โค้ดเราเป็นคนรัน function จริงๆ แล้วส่งผลกลับให้ Claude

5. Claude ตอบผู้ใช้ด้วยข้อมูลจริง
✅ เมื่อไหรควรใช้:
→ อยากให้ Claude ดึงข้อมูล real-time (ราคาหุ้น, อากาศ)
→ อยากให้ Claude ส่งอีเมล, บันทึกข้อมูล, เรียก API ภายนอก
→ อยากสร้าง chatbot ที่ตอบได้หลายแบบ โดยไม่ต้องเขียน if/else ทุก case

บทที่ 22 — ระดับ 3
Agentic Loop

Agentic Loop คือวงจรที่ Agent ทำงานซ้ำๆ โดย คิด → ทำ → ดูผล → คิดใหม่ → ทำใหม่ จนกว่าจะเสร็จ

Automation = สายพานการผลิต (ทุก step ถูกกำหนดไว้ล่วงหน้า)
Agentic Loop = นักสืบ (รับคดี → สืบหาเบาะแส → ปรับทิศทาง → คลี่คลายคดี)

องค์ประกอบ

1. Perceive → รับรู้ input และผลลัพธ์จาก step ก่อน
2. Think    → Claude วิเคราะห์ว่าต้องทำอะไรต่อ
3. Act      → เรียก Tool, รันโค้ด, เขียนไฟล์
4. Observe  → ดูผลลัพธ์ว่าตรงเป้าหมายไหม
5. วนซ้ำ  → จนเสร็จหรือถึง limit ที่กำหนด

Use Case: Research Agent วิเคราะห์หุ้น ADVANC

รอบ 1: ค้นหาข้อมูลพื้นฐาน ADVANC
รอบ 2: ดึงผลประกอบการ 4 ไตรมาสล่าสุด
รอบ 3: ค้นหาข่าวล่าสุดและ sentiment
รอบ 4: วิเคราะห์คู่แข่ง TRUE, DTAC
รอบ 5: ประเมิน valuation
รอบ 6: สรุปและให้ recommendation
รอบ 7: ตรวจสอบว่าครบถ้วนดีไหม → ครบ → จบ Loop

Tips ประหยัดเงินและ Optimize การใช้ API
💡 ตัวอย่างความต่างชัดๆ
สรุป Oppday 200 ไฟล์: Opus ~$54 / Sonnet ~$10 / Haiku ~$2
เลือก Model ให้ถูกงาน = ประหยัดได้ 80-90%

Tip 1: เลือก Model ให้เหมาะกับงาน

Modelเหมาะกับราคา
HaikuClassification, แปลภาษา, สรุปสั้นๆถูกที่สุด
Sonnet ⭐สรุปเอกสารยาว, วิเคราะห์, เขียนโค้ดสมดุล
OpusReasoning ซับซ้อน, ความแม่นยำสูงสุดแพงที่สุด

Tip 2: เขียน Prompt ให้กระชับ

❌ ฟุ่มเฟือย (เสีย token)
"สวัสดีครับ Claude ผมอยากให้คุณช่วยผมสรุปเอกสารนี้ ถ้าคุณมีเวลา ช่วยสรุปสั้นๆ ขอบคุณมากนะครับ"
✅ กระชับ (ประหยัด 60%)
"สรุปเอกสารนี้เป็น 5 bullet points ภาษาไทย"

Tips อื่นๆ ที่สำคัญ

Tip 3: Prompt Caching
System Prompt ยาว → จ่ายครั้งแรกครั้งเดียว
→ ครั้งถัดไปถูกกว่า 90%

Tip 4: Batch Processing แทน Real-time
รวม request ทั้งหมด → ส่งพร้อมกัน → ถูกกว่า ~50%
เหมาะกับ: batch summarize Oppday ทุกคืน

Tip 5: รับมือ Rate Limits (Error 429)
✅ ใส่ delay รอ 1-2 วินาทีระหว่างทุก API call
✅ เขียน retry logic
✅ รัน batch ช่วง off-peak เช่น กลางคืน

Tip 6: ดูการใช้งานที่ console.anthropic.com → Usage
